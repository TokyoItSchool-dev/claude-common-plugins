# Python Coding Conventions

Language-agnostic rules (naming, file size, immutability, error handling, input validation) are in `core-dev:coding-standards`. This skill adds the Python-specific rules.

## Python Version

- Declare the floor in `pyproject.toml` as `requires-python = ">=3.11"`. FastAPI 0.162.7 and pydantic-settings 2.16.3 (the versions checked for this skill, 2026-11-14) declare `Requires-Python: >=3.11`. pip-audit needs 3.10 or later. When a newer FastAPI raises its floor, raise `requires-python` with it.
- The Python minor version installed in a Claude Code cloud session is not documented. Check it with `python3 -V`, and pin the project's version with `uv python pin <version>`, which writes `.python-version`. Commit `.python-version`.
- This section is the one place that states the version floor. Other skills in this plugin refer to it.

## uv Projects

- Manage the project with uv. Dependencies are in `pyproject.toml`; `uv.lock` is generated by uv. Commit `uv.lock` and do not edit it by hand (uv documentation: the lock file "should be checked into version control" and "should not be edited manually").
- Add dependencies with `uv add <package>` and development tools with `uv add --dev <package>` (they go to the `dev` dependency group, which `uv sync` and `uv run` install by default).
- Prepare the environment with `uv sync` when `.venv/` does not exist or `uv.lock` has changed.
- Run every tool through `uv run` (`uv run pytest`, `uv run ruff check .`). `uv run` locks and syncs the project before it runs the command. In checks, add `--locked` (`uv run --locked pytest`, `uv sync --locked`) so that a lock file that does not match `pyproject.toml` fails instead of being rewritten.
- Do not install packages with `pip install` into the system Python or into `.venv/` by hand; the next `uv sync` removes what the lock file does not list.

```toml
[project]
name = "app"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "fastapi",
    "pydantic-settings",
]

[dependency-groups]
dev = [
    "httpx2",
    "mypy",
    "pip-audit",
    "pytest",
    "ruff",
]

[build-system]
requires = ["uv_build>=0.11,<0.12"]
build-backend = "uv_build"
```

- Use the `src` layout (`src/<package>/`). pytest's good-practices page recommends it, and `uv_build` expects it by default.
- The HTTP client package that FastAPI's `TestClient` needs (`httpx2` above) is explained in `pytest-testing`.

## Package Index Access in a Cloud Session

- In a Claude Code cloud session with the default (Limited) network level, `pypi.org` and `files.pythonhosted.org` are on the default allowlist, so `uv sync` and `uv add` work without changing the environment.
- A private package index, or any other host the project needs at install or test time, must be added to the environment's allowed hosts before it can be reached. Do not work around a blocked host.
- pip-audit's default vulnerability service is PyPI. `--vulnerability-service osv` sends requests to `api.osv.dev`, which the stack research did not find on the default allowlist; use the default service in a cloud session unless that host has been allowed.

## Check Commands

The stack check script (`scripts/stack-check.sh` in a repository made from the template) lists the checks once. The template design gives this set for the Python API stack:

```bash
#!/bin/bash
set -euo pipefail
if [ ! -f pyproject.toml ]; then
  echo "::warning::pyproject.toml not found; skipping checks"
  exit 0
fi
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy .
uv run --locked pytest
uv run --locked pip-audit --skip-editable
```

The script name comes from the project template. A project without it runs the same commands directly.

- `ruff format --check` and `--locked` are additions to the design's example; `--skip-editable` stops pip-audit from reporting the project itself, which uv installs as an editable package and which is not on PyPI (checked with pip-audit 2.10.1).
- With no arguments, `pip-audit` audits the environment it runs in, so `uv run pip-audit` audits the project's `.venv/`. It exits with code 1 when it finds a known vulnerability.
- How to run tests and report results is in `core-dev:test-run-discipline`.

## Ruff and mypy Configuration

```toml
[tool.ruff.lint]
extend-select = ["I", "B", "UP", "TID251"]

[tool.mypy]
strict = true
plugins = ["pydantic.mypy"]
```

- `extend-select` adds rules to Ruff's default set: `I` (import sorting), `B` (flake8-bugbear), `UP` (pyupgrade), and `TID251` (banned APIs, used in Pure Domain Modules below). Ruff takes its target Python version from `requires-python` when `target-version` is not set.
- Format with `ruff format` (default line length 88). Do not hand-format against it.
- Run mypy with `strict = true`. Do not turn off strict options to make an error go away. The `pydantic.mypy` plugin makes mypy check Pydantic model constructors.

## Type Hints

- Annotate the parameters and return type of every function, including tests (`-> None`) and fixtures.
- Write `X | None`, `list[str]`, and `dict[str, int]`, not `Optional[X]`, `List`, or `Dict`. Import abstract types from `collections.abc` (`Iterator`, `Callable`, `Sequence`).
- Do not use `Any` for data whose shape you know. Data from outside the process (request bodies, JSON files, environment variables, responses from other services) is validated with a Pydantic model or `TypeAdapter` before use; see `fastapi-patterns`.
- Do not pass untrusted input to `subprocess` with `shell=True`. Do not load untrusted data with `pickle` or `yaml.load`; use `yaml.safe_load`.
- Do not use a bare `# type: ignore`. When an ignore is unavoidable, name the error code and the reason on the same line: `# type: ignore[attr-defined]  # library has no stubs`.
- Use `datetime` values with a time zone (`datetime.now(UTC)`, `datetime(2026, 1, 1, tzinfo=UTC)`). A naive `datetime` cannot be compared with an aware one.

## Pure Domain Modules

Keep business rules (state derivation, calculations, validation rules) in modules that do no I/O and do not read the current time:

- The current time is a parameter (`now: datetime`), not `datetime.now()` inside the rule.
- No database, HTTP, file, or framework imports (`fastapi`, `pydantic_settings`, database drivers).
- Enforce the clock rule with Ruff's banned-API rule, and allow the clock only in the module that provides it as a dependency:

```toml
[tool.ruff.lint.flake8-tidy-imports.banned-api]
"datetime.datetime.now".msg = "Pass the current time as an argument; read the clock only in dependencies.py."

[tool.ruff.lint.per-file-ignores]
"src/app/dependencies.py" = ["TID251"]
```

```python
"""Business rules. No I/O, no framework imports, no clock reads."""

from datetime import datetime, timedelta


def is_stale(last_updated_at: datetime, now: datetime, threshold_days: int) -> bool:
    """Return True when the last update is at least threshold_days old (AC-001)."""
    return now - last_updated_at >= timedelta(days=threshold_days)
```

## Error Handling

- Raise specific exception classes that carry the context (`ProjectNotFoundError(project_id)`), not `Exception("...")`.
- Do not write `except:` or `except Exception: pass`. Catch the exceptions you can handle; let the rest reach the framework's error handler (see `fastapi-patterns`).
- When converting one exception into another, use `raise NewError(...) from err`, or `from None` when the original is not useful to the caller.
- Log with the `logging` module (`logger = logging.getLogger(__name__)`), not `print`. Do not log secrets or request bodies that may contain them.

## Comments

- Put a docstring on public modules, classes, and functions that states what it is for and any rule it implements.
- When code implements an acceptance criterion or an Issue, cite it in the docstring or comment (`AC-007`, `#12`).

## Anti-Patterns to Avoid

| Anti-Pattern | Fix |
|---|---|
| `pip install` into the system Python or `.venv/` | `uv add` and `uv sync` |
| Hand-edited or uncommitted `uv.lock` | Let uv write it; commit it |
| `uv run pytest` in checks without `--locked` | `uv run --locked pytest` |
| Missing parameter or return annotations | Annotate everything; run mypy with `strict = true` |
| `Optional[X]`, `List[X]` | `X \| None`, `list[X]` |
| `json.loads(...)` result used as a dict without validation | Validate with a Pydantic model or `TypeAdapter` |
| `datetime.now()` inside business logic, or naive datetimes | Pass `now: datetime`; use `UTC` |
| `except Exception: pass` | Catch specific exceptions; let others reach the handler |
| `subprocess` with `shell=True` on untrusted input, or `pickle` / `yaml.load` on untrusted data | Pass an argument list without `shell=True`; use `yaml.safe_load`, or a Pydantic-validated format such as JSON |
| Bare `# type: ignore` | `# type: ignore[code]` with a reason |

## Recommended Hooks (configure in your project settings)

These are suggestions to wire up as PostToolUse/Stop hooks in your own settings, not something this plugin installs:

- After editing `.py` files: run `uv run ruff format <file>` and `uv run ruff check --fix <file>`.
- Before ending a session with broad Python changes: run `uv run mypy .` and `uv run pytest`.
