# 構成案パッケージ図 レビュー記録

実例（研修教材 6 冊の再編、図 8 枚、2026-10）で見つかった問題と、部品に反映した修正。

## 共通

- 【記法】移動の矢印が実線で、依存に見えた → 破線＋開いた矢じりに統一し、凡例に «move» を書いた。
- 【記法】送り出した節を元の教材から消していた → 「旧 …」として残し、灰の点線（out）で描くようにした。
- 【意味】状態の塗りが 流用＝灰、新規＝黄 で、UML の青系と合わなかった → 流用＝薄い青、新規＝濃い青の破線、外す＝灰 に変えた。
- 【意味】流用の節にも出どころの注記を全部書いて読めなくなった → 会議資料では移動に関わる注記だけ残す（`simplify` の考え方を references に記載）。

## 構成案（plan）

- 【見た目】右の箱へ入る矢印が 3 本重なり、どの節から来たか追えなかった → 矢印ごとに縦レーンを 7px ずらし、同じ箱への到着 y を 22px ずつ分散させた。
- 【見た目】右の箱が上に固まり、矢印が長く斜めに走った → 箱をつながる節の平均 y に置き、重なるときだけ下へずらすようにした。
- 【見た目】注記が箱からはみ出した → 16px へ自動で縮め、それでも入らなければ末尾を「…」にした。
- 【見た目】節の箱が全部同じ白で、新規と改写の区別が付かなかった → 新規は濃い青の破線にして一目で分かるようにした。
- 【意味】矢印の向き（節→箱、箱→節）を逆に書いた spec で KeyError になった → id の組を見て自動で向きを正すようにした。

## 集約・移行（migration）

- 【見た目】左のパッケージ群が外枠からはみ出した → グループ間の余白を高さの見積もりに入れた。
- 【見た目】7 本の矢印が同じ x を通って 1 本に見えた → レーンを 8px ずつずらした。
- 【意味】移動先が同じ箱に 2 本入るとき、どちらが「第1〜3章だけ」か分からなかった → 矢印にラベル（白い下地付き）を付けられるようにした。
