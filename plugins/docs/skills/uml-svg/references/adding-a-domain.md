# 分野ファイルが無い図を描く／分野を追加する

ER図、クラウド構成図、フローチャート、ネットワーク図など、`references/` に分野ファイルが無い図を頼まれたときに読む。

## まず汎用部品だけで描く

- 箱は `plain` か `box`、分岐は `diamond`、線は `edge`、文字は `text` で描く。足りない記号は `raw()` でSVGを直接書く。
- 記法は、その分野で最も広く使われている標準に従う。
  - 例：ER図ならIE記法（カラスの足）かChen記法のどちらかに統一する。
  - 例：フローチャートなら JIS X 0121 / ISO 5807 の記号に従う。
  - どの標準に従ったかを、レビュー記録の冒頭に書く。
- 標準がはっきりしない分野では、凡例（記号の意味）を図の中に入れる。

## 作図後の検証

分野ファイルが無いので、次の問いを自分で立てて図に当てる。

1. **記号の意味**：同じ記号が、図の中で2つの意味に使われていないか。逆に、同じ意味の要素に2種類の記号を使っていないか。
2. **線の意味**：線の種類（実線か破線か）、矢じりの種類、矢印の向きは、その分野の標準と一致しているか。
3. **流れの完全性**：始まりと終わりがあるか。行き止まりや、合流先の無い分岐が無いか。
4. **数の整合**：多重度・カーディナリティ・冗長構成の台数が、文章の説明と一致しているか。
5. **ほかの図との整合**：同じシステムの別の図と、名前や構成が食い違っていないか。

見つけた問題は、UMLのときと同じく【記法】と【意味】に分けて `*_review.md` に記録する。

## 分野ファイルを追加する手順

分野ファイルは、実際に描いて検証した経験をもとに書く。想像で書いたチェックリストは品質を下げるので、描く前に用意しない。

1. その分野の図を最低3枚描き、上の検証を回して、見つかった誤りを記録する。
2. `references/<分野>.md` を作る。構成は `uml.md` に揃える。
   - その分野用の部品（新しく作った部品）の表
   - 記法チェックリスト（実際に見つかった誤りから作る）
   - 図種ごとの組み立て方
   - レビュー記録の書き方
3. 新しい部品は `scripts/diagsvg.py` に追加する。配色は既存の定数を使い、新しい色を増やさない。
4. 生成コード・レビュー記録・完成見本を `examples/<分野>/` に置く。
5. SKILL.md の「分野別ルール」の表に1行追加する。
6. 必要であれば、SKILL.md の description に分野名を追加する。
