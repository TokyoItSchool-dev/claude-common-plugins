# UML 分野ルール

UML図を描くとき、または再現するときに読む。汎用の手順は SKILL.md、部品の実装は `scripts/diagsvg.py` にある。
実例は `examples/uml/` にある。

- `diagrams.py`：8図の生成コード。新しいUML図の座標の雛形にする。
- `UML_review.md`：元画像の誤りを記録したレビュー記録の例。
- `out/`：完成見本。

## UML用の部品

| 部品 | 用途 |
|---|---|
| `node3d(..., stereotype="device")` | 配置図のノード（立方体） |
| `artifact(..., stereotype="artifact"/"executionEnvironment", icon=...)` | 配置図で、ノードの中に置く要素 |
| `component_box(..., stereotype=None/"database", icon=...)` | コンポーネント。タブの無い矩形 |
| `lollipop(x,y)` / `socket(x,y,toward)` | 提供インターフェース（白丸）／要求インターフェースの受け口（半円） |
| `classbox(x,y,w, name, attrs, ops)` | クラス（3区画）。高さは自動で決まる |
| `diamond_end(x,y,angle,filled)` | コンポジション（塗りつぶし）／集約（白抜き） |
| `start()` / `final()` | 開始ノード・開始状態／終了ノード・終了状態 |
| `badge(x,y,n)` | シーケンス図のメッセージ番号 |
| `edge(arrow="filled")` | 同期メッセージ専用の塗りつぶし三角 |
| `folder(...)` | パッケージ専用。コンポーネントや成果物には使わない |

## 記法チェックリスト

### 全図共通

- **矢じりの種類**
  - 塗りつぶし三角：シーケンス図の同期メッセージだけ。
  - 開いた矢じり（V字）：遷移、制御フロー、依存、誘導可能性、応答メッセージ。
  - 白抜き三角：汎化（継承）。
- **ステレオタイプの表記**
  - ギュメ `«include»` を使う。半角の `<<include>>` は使わない。
- **線端の黒丸**
  - UML 2.5 では「所有」を表す記号になる。飾りとして付けない。

### 配置図

- ノード内に置くソフトウェアは «artifact»（矩形＋右上に成果物アイコン）にする。フォルダ形はパッケージの記法なので使わない。
- 実行基盤（ブラウザ、DBMSなど）は «executionEnvironment» にする。
- 機器のノードには «device» を付ける。
- 通信路は2ノード間を結ぶ関連なので、分岐させない。行き先ごとに別の線を引く。
- 通信路にはプロトコル名をラベルとして付ける。

### コンポーネント図

- コンポーネントはタブ無しの矩形にし、コンポーネントアイコンか «component» を付ける。
- 提供インターフェース（白丸）は、提供する側から実線でつなぐ。
- 利用する側は、白丸へ破線の依存矢印を引くか、受け口（半円のソケット）を白丸にかぶせて組立コネクタにする。
- DBへのアクセスは «use» 依存で表す。DB自体には «database» を付ける。
- 意味の整合を確認する。例：どのサービスがどのDBを使うかが、他の図と一致しているか。

### ステートマシン図

- 遷移ラベルは `イベント [ガード] / 効果` の形で書く。かっこ書きの補足は使わない。
- 終わりのある状態（キャンセルなど）からは、終了状態への遷移を描く。
- 遷移の向きとイベントの意味が合っているか確認する。
  - 例：「梱包完了」で「出荷準備中」に入るのは逆。正しくは `支払い済み →(出荷指示)→ 出荷準備中 →(出荷 [梱包完了])→ 発送済み`。
- 状態名は上の区画に入れ、下の区画に内部振る舞い（entry / do）を書く。
- 他の図で起こりうる事象（決済失敗など）は、自己遷移などで表す。

### アクティビティ図

- アクションに入力フローを2本以上直接入れない。暗黙の合流になり、全部そろうまで待つため、ループが動かなくなる。
  - ループの戻り先には、マージノード（ひし形）を置く。
- 分岐の条件は角かっこのガードで書く（`[成功]` `[失敗]`）。
- 開始ノード・終了ノードは記号だけで表す。「開始」「終了」の文字は付けない。

### シーケンス図

- すべてのメッセージに名前を付ける。応答メッセージにも付ける。
- 依頼（同期呼び出し）と応答を取り違えない。
  - 例：「在庫引当」は依頼。応答は「引当結果」。
- 同期呼び出しをしている間は、呼び出し元の活性区間を応答が返るまで続ける。
- 送信の瞬間には、送信元が活性になっているようにする。

### クラス図

- 線の途中に置く三角は「関連名の読む向き」を示す記号。線の上ではなく、関連名の横（`所有する ▶`）に置く。
- 誘導可能性は、線端の開いた矢じりで表す。
- 全体と部分で運命を共にする関係（注文と注文明細など）は、コンポジション（全体側に塗りひし形）にする。
- 多重度が他の図と矛盾しないか確認する。
  - 例：未払いの注文があるなら、注文と支払いは `1 : 0..1`。
- 状態を String で持たせず、ステートマシン図と一致する «enumeration» を型にする。

### ユースケース図

- «include» の矢印は、基底ユースケースから包含されるユースケースへ向ける。
- «extend» の矢印は、拡張する側から基底ユースケースへ向ける。
  - 独立した機能を extend でつながない。
- 外部システムのアクターは、棒人間か «actor» の矩形にする。アイコンだけで表さない。
- 関連線の端に黒丸を付けない。

### パッケージ図

- 依存は破線と開いた矢じりで表し、«use» または «import» を付ける。
- 層の依存方向を一方向にそろえる（上位層から下位層へ）。

### 図どうしの整合

- クラス図の «enumeration» と、ステートマシン図の状態名を一致させる。
- シーケンス図の参加者が、コンポーネント図と配置図にも現れることを確認する。
- 遷移の効果（返金処理など）が、クラス図の操作として定義されていることを確認する。

## 図種ごとの組み立て方

### 配置図

- ノード：`node3d(..., stereotype="device")`
- 中に置くソフトウェア：`artifact(..., icon=...)`
- ブラウザなどの実行基盤：`artifact(..., "ブラウザ", "executionEnvironment", sfs=15)`
- 通信路：`edge(arrow=False)` を2ノードごとに1本ずつ引き、プロトコル名のラベルを付ける。

### コンポーネント図

- コンポーネント：`component_box()`。DBは `stereotype="database", icon="db"` を指定する。
- 提供インターフェース：提供側から実線を引いて `lollipop()` を置く。利用側からは白丸へ `edge(dash=True)` を引く。
- 組立コネクタ：同じ座標に `lollipop()` と `socket()` を置き、両側から実線でつなぐ。
- DBへのアクセス：`edge(dash=True)` に `stereo("use")` を添える。

### ステートマシン図

- 状態：`box(band=50)` を使い、上の区画に状態名、下の区画に `entry / ...` や `do / ...` を書く。
- 遷移：`イベント [ガード] / 効果` のラベルを付ける。
- 自己遷移：コの字型のパスで、同じ状態に戻す。
- 終了状態：終わりのある状態ごとに `final()` へつなぐ。

### アクティビティ図

- スイムレーン：`raw(layer="bg")` で描く。
- 判断ノードとマージノード：どちらも `diamond()` を使う。
- ガード：`[..]` で書く。
- 戻りのフロー：必ずマージノードに入れる。

### シーケンス図

- 同期メッセージ：`edge(arrow="filled")`
- 応答：`edge(dash=True)` で開いた矢じりにし、名前を付ける。
- 番号：`badge(n)` を付ける。
- 活性区間：同期呼び出しの間は途切れさせない。

### クラス図

- クラス：`classbox()`
- コンポジション：`diamond_end()` を全体側に置く。
- 誘導可能性：線端の開いた矢じりで表す。
- 関連名の読む向き：関連名の横に「▶」を添える。
- 列挙型：«enumeration» の箱を作り、ステートマシン図の状態と一致させる。

### ユースケース図

- システム境界：`raw(layer="bg")` で描く。
- ユースケース：`ellipse()`
- «include»：基底から包含先へ矢印を向ける。
- «extend»：拡張側から基底へ矢印を向ける。
- 外部システムのアクター：«actor» の矩形で描く。

### パッケージ図

- パッケージ：`folder()`（パッケージ専用）
- 依存：破線の開いた矢じりに «use» を付ける。

## レビュー記録の書き方

- 問題ごとに1行で書く：`【記法】または【意味】 問題の内容 → 修正内容`
- 図ごとに見出しを立てる。全図に共通する問題は「共通」の見出しにまとめる。
- 書き方の実例は `examples/uml/UML_review.md` にある。
