# 構成案パッケージ図（再編・集約の提案図）

教材・モジュール・リポジトリのように「入れ物の中身をどう組み替えるか」を関係者に見せる図を描くときに読む。
UML パッケージ図の見た目（タブ付きの枠）を借り、中身の 1 行 1 行を「流用・改写・新規・外す」で塗り分け、
入れ物をまたぐ移動を «move» の破線矢印で表す。MTG の事前共有資料や変更点説明で使う。

出発点は、研修教材 6 冊の再編を 1 回の MTG で承認まで持っていった実例（2026-10）。
以下のルールはその図 8 枚を描いて直した結果から作った。

## 部品（scripts/pkgplan.py）

| 関数 | 用途 |
|---|---|
| `plan_diagram(spec, path)` | 構成案。左に対象パッケージ（部・章 → 節）、右に関係先パッケージ、間を «move» でつなぐ。高さは自動 |
| `migration_diagram(spec, path)` | 集約・移行。左に現状のパッケージ群、右に移行先、間を «move» でつなぐ。高さは自動 |
| `STATUS` | 節の状態 → （塗り、破線、文字色、凡例の文言）。文言を変えたいときはここを書き換える |

どちらも `diagsvg.Doc` の上に載っている。細部を変えたいときは `pkgplan.py` を作業ディレクトリへコピーして直す。
生成例は `examples/package-plan/diagrams.py`、完成見本は `examples/package-plan/out/`。

### plan_diagram の spec

```python
{
  "title": "003 Web開発入門",            # ヘッダー。空白の前がアクセント色
  "subtitle": "部・節の構成案",
  "package": "003 Web開発入門 [WEB003]",  # 左の大きなパッケージ名
  "groups": [                              # 部・章。上から順に積む
    ("第1部 Web の仕組み", [
      ("p11", "1-1 ブラウザとサーバー", "reuse", ""),        # (id, 表示名, 状態, 注記)
      ("p15", "旧 1-5 サーバーの設置場所", "out", "→ 004 へ"),
    ]),
  ],
  "boxes": [                               # 右の関係先。kind は "pkg"（青）か "ref"（灰＝参照のみ）
    ("b004", "→ 004 インフラ入門", ["サーバーとデータセンター"], "pkg"),
  ],
  "arrows": [("p15", "b004", "out")],      # (節 id, 箱 id, 向き)。out = 送り出す、in = 受け入れる
  "notes": ["脚注"],                        # 省略可。左パッケージの最下部
  "legend": ["reuse", "rewrite", "new", "out"],  # 省略可。凡例に出す状態
  "status_labels": {"out": "このモジュールから外す"},  # 省略可。凡例の文言を題材に合わせる
}
```

状態は 4 つ。

| 状態 | 見た目 | 意味 |
|---|---|---|
| `reuse` | 薄い青、実線 | 元の内容をそのまま使う |
| `rewrite` | 白、破線 | 内容を書き直す（位置は残る） |
| `new` | 濃い青、破線 | 新しく書く |
| `out` | 灰、点線、灰文字、影なし | この入れ物から外す（行き先は注記と矢印で示す） |

### migration_diagram の spec

```python
{
  "title": "020_Web入門 への集約", "subtitle": "元フォルダから新フォルダへ（案 1）",
  "left_title": "リポジトリの現状",
  "left": [("080_基礎", ["005_Webアプリケーション基礎 [STD005]"], "pkg")],   # (見出し, 行, kind)
  "right_title": "02_個別研修教材/020_Web入門（案 1）",
  "right": ["001_コンピューターの基礎 [WEB001]", "002_PC操作基礎 [WEB002]"],  # 移行先の箱
  "right_notes": ["番号は実施順に振り直し"],                                     # 省略可
  "moves": [(0, 0, 1), (1, 1, 0, "第1〜3章")],  # (左の見出し index, 行 index, 右 index, ラベル省略可)
  "footer": "破線の矢印は «move»（移動）。",     # 省略可
}
```

## 記法チェックリスト

- 移動は破線＋開いた矢じりで、`«move»` を凡例に書く。実線や塗りつぶしの矢じりにしない（依存や継承に見える）。
- 送り出す節は元の入れ物に **「旧 …」として残し、`out` で描く**。消してしまうと「どこから来たか」が追えない。
- 受け入れる側の節にも、注記に `← 旧 1-6` のように出どころを書く。矢印と注記の両方で読めるようにする。
- 1 つの節から 2 か所へ送らない。分けるなら節を 2 行にする。
- 右の箱（関係先）は、矢印がつながるものだけ置く。参照のみの箱は `ref`（灰）にして、移動先（青）と区別する。
- 状態の塗りは 4 種類で固定する。「要検討」のような 5 つ目の状態は、注記に【要確認】【提案】と書いて表す。
- 凡例は必ず入れる。塗りの意味は分野標準ではなく、この図の約束だから。

## 見た目のチェックリスト

- 矢印が重なって読めないときは、レーン分けが効いているか確認する（`plan_diagram` は 1 本ごとに 7px ずらす）。
  それでも重なるなら、右の箱の順番を矢印の出所の順に並べ替える。
- 注記は自動で 16px まで縮み、収まらなければ末尾を「…」にする。「…」が出たら注記を短くする（矢印の相手だけ書けば足りる）。
- 1 図あたり節は 20 行まで。超えたら部ごとに図を分ける。
- 右の箱の説明行は 2 行まで、1 行は全角 18 字まで（超えると自動で縮む・「…」になる）。中身の説明は本文に書く。
- 凡例の「この教材から外す」は題材に合わせて `status_labels` で書き換える（モジュールなら「このモジュールから外す」）。

## 情報量を減らすコツ（会議資料のとき）

- 出どころの注記は、移動に関わるもの（←、→、【提案】【要確認】）だけ残す。流用の節に「← 旧 2-2」と全部書くと読めなくなる。
- 注記が「、」で続くときは最初の 1 句だけ残す。
- 決めたい箇所だけ【提案】【要確認】を付け、決まったら消す。図が「残る論点の一覧」として働く。

## レビュー記録の書き方

`uml.md` と同じ。`【記法】または【意味】 問題 → 修正` を図ごとに 1 行ずつ。
実例は `examples/package-plan/package-plan_review.md`。
