# コードレビュー

## レビューの必須トリガー

- コードを書いた・変更した直後
- 共有ブランチへのコミット前 / PR マージ前
- セキュリティ関連（認証・決済・ユーザーデータ）やアーキテクチャ変更時

## 実装者とレビュアーの分離

あるエージェントが実装したものは、必ず別のエージェントインスタンスにレビューさせる。同一の作業主体に自己レビューさせない。

## 深刻度レベル

| レベル | 意味 | アクション |
|--------|------|-----------|
| CRITICAL | 脆弱性・データ損失リスク | **BLOCK**（マージ前に必須修正） |
| HIGH | バグ・重大な品質問題 | **WARN**（マージ前に修正すべき） |
| MEDIUM | 保守性の懸念 | **INFO**（可能なら修正） |
| LOW | スタイル・軽微な提案 | **NOTE**（任意） |

## レビューワークフロー

1. `git diff` で変更を把握する。
2. セキュリティチェックリストを先に確認する（`core-dev:security-check` スキル）。
3. コード品質チェックリストを確認する（`core-dev:coding-standards` スキル）。
4. 関連テストを実行する。
5. カバレッジ 80%+ を確認する。
6. 実装者とは別のエージェントで詳細レビューを行う。

## よく捕まえる問題

- **セキュリティ**: ハードコード資格情報、SQL インジェクション、XSS、パストラバーサル、CSRF 欠如、認証バイパス。
- **品質**: 巨大関数（分割）、巨大ファイル（モジュール抽出）、深いネスト（早期リターン）、エラー処理欠如、破壊的変更、テスト欠如。
- **パフォーマンス**: N+1 クエリ（JOIN / バッチ化）、ページネーション欠如（LIMIT）、無制限クエリ、キャッシュ欠如。

## 承認基準

- **承認**: CRITICAL / HIGH なし
- **警告付き**: HIGH のみ（注意してマージ）
- **ブロック**: CRITICAL あり

## Pre-Review Requirements

Before requesting review, ensure:

- All automated checks (CI/CD) are passing
- Merge conflicts are resolved
- Branch is up to date with target branch
