# セキュリティ

## コミット前の必須チェック

- [ ] ハードコードされた秘密情報がない（API キー・パスワード・トークン）
- [ ] すべてのユーザー入力を検証している
- [ ] SQL インジェクション対策（パラメータ化クエリ）
- [ ] XSS 対策（HTML サニタイズ）
- [ ] CSRF 対策が有効
- [ ] 認証・認可を検証済み
- [ ] エンドポイントにレート制限
- [ ] エラーメッセージが機微情報を漏らさない

## 秘密情報の管理

- ソースコードに秘密情報をハードコードしない。環境変数またはシークレットマネージャを使う。
- 起動時に必須の秘密情報が揃っているか検証する。
- 漏洩の可能性があるものはローテートする。

## セキュリティ対応プロトコル

セキュリティ問題を発見したら:

1. 即座に停止する。
2. セキュリティ観点のレビューを実施する。
3. CRITICAL を先に修正する。
4. 露出した秘密情報をローテートする。
5. 同種の問題がないかコードベース全体を確認する。

## セキュリティレビューのトリガー

以下に触れる変更は特に慎重にレビューする。

- 認証・認可
- ユーザー入力処理
- DB クエリ
- ファイルシステム操作
- 外部 API 呼び出し
- 暗号処理
- 決済・金融処理
