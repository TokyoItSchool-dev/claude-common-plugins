# テスト / TDD

## カバレッジ最低 80%

必要なテスト種別（すべて）:

1. **ユニットテスト**: 個々の関数・ユーティリティ・コンポーネント
2. **統合テスト**: API エンドポイント・DB 操作
3. **E2E テスト**: 重要なユーザーフロー

## テスト駆動開発（TDD）

1. テストを先に書く（RED）
2. 実行して失敗を確認する
3. 通す最小実装を書く（GREEN）
4. 実行して成功を確認する
5. リファクタする（IMPROVE）
6. カバレッジ 80%+ を確認する

## テスト失敗時の切り分け

- テストが互いに干渉していないか（テスト分離）を確認する。
- モックの設定が正しいかを確認する。
- 原則として実装を直す。テスト側が誤っている場合に限りテストを修正する。

## テスト構造（AAA パターン）

- Arrange（準備）→ Act（実行）→ Assert（検証）の構造を推奨する。
- テスト名は振る舞いを説明する記述的な名前にする（例: `returns empty array when no markets match query`）。
